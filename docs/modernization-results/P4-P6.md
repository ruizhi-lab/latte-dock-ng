# P4–P6: conditional performance candidates

Status: Deferred after early evidence evaluation. The Fedora Debug trace
identified candidate work, but did not establish a correctness-preserving
change with measurable Release benefit. No production code was changed.

## Evidence available

The P0 Fedora Release characterization records process-family CPU, context
switches and memory for idle, hidden-idle, multi-window and hover scenarios.
The five independent hover starts and live edge sequence are documented in
[P0](P0.md), with raw samples in
[P0-hover-aa-current-release-2026-10-01.jsonl](P0-hover-aa-current-release-2026-10-01.jsonl)
and [P0-edge-transitions-2026-10-01.jsonl](P0-edge-transitions-2026-10-01.jsonl).
These data establish repeatable scenarios but no before/after saving. The edge
screenshots establish the selected setting and settled visible geometry, not
layout-pass counts or frame-time tails.

## Candidate decisions

- **P4, shared per-view task query:** process-level samples cannot isolate task
  query cost or establish whether a shared query reduces work without changing
  model ownership. Defer until a profiler identifies duplicate query cost and
  an instrumented workload can compare query counts and task behavior.
- **P5, effect/layer allocation:** no QML allocation, texture, GPU-memory or
  frame-time instrumentation is present in this baseline. Defer until a trace
  identifies repeated allocations and a visual stress scenario can prove
  equivalent output while measuring reduced allocation or frame cost.
- **P6, pure-QML module build-time caching:** P0 runtime characterization does
  not measure QML compile/import time or rebuild scope. Defer until a clean and
  incremental build profile identifies a module with material repeated cost;
  any future change must preserve import and installation contracts.

Do not infer optimization opportunity from total process memory or CPU alone.
Reopen each candidate independently when its required metric is available, and
select a narrow change with a correctness-preserving acceptance threshold.

## Early evaluation — 2026-10-01

The Fedora 44 VM was running Plasma Wayland. Its user-mode Debug build was
rebuilt from the checked branch snapshot with `bash install.sh --user Debug
--jobs 8`. A first QML Profiler attempt against the previously installed
Release binary did not establish the debugger connection and produced no valid
trace; that attempt is excluded. The Debug retry connected successfully and
captured 30 seconds of startup/idle tracing with the following command (after
importing the active Plasma session variables and sourcing
`~/.config/latte-dock-ng/dev-env.sh`):

```bash
/usr/lib64/qt6/bin/qmlprofiler --verbose \
  --include compiling,creating,binding \
  --output /tmp/latte-p4p6.qmltrace \
  /home/fedora/.local/bin/latte-dock-ng --replace --debug \
  --log-file /tmp/latte-ng-profile.log
```

The trace contained 519,516 event ranges: 380,893 binding ranges, 134,687
creation ranges and 3,936 compilation ranges over 209 QML file basenames. The
aggregate was collected from a single 30-second instrumented Debug start; event
durations overlap and are profiler data, not wall-clock savings or Release
performance. The 40 MB raw trace was kept only under `/tmp` while summarizing
and then deleted from both machines.

### P4 — per-applet task queries

Static inspection of `containment/package/contents/ui/applet/AppletItem.qml`
shows that a full `TaskManager.TasksModel`, `VirtualDesktopInfo` and
`ActivityInfo` are created only when the applet resolves at least one tracked
application ID and the task indexer is unavailable. Each such model is
screen-, desktop- and activity-filtered for its containing view; applet IDs are
filtered in the subscriber after querying. The trace observed six TasksModel
instances: two at each of `plasmoid/.../main.qml:683`,
`containment/.../Tasks.qml:16` and `AppletItem.qml:1579`. It observed three
VirtualDesktopInfo and three ActivityInfo instances, one at each of those
three call sites. This does not establish whether multiple tracker models
belong to one view, so it does not demonstrate duplicate tracker work or a
resource benefit from sharing. Keep P4 deferred until a representative
multi-tracked-applet view and a model/query counter can show duplicate work
that a per-view owner would remove. Any prototype must keep the distinct
grouping/launcher model at the main task manager separate.

### P5 — shadow layer/effect

`ExternalShadow.qml` contains one `layer.enabled` rectangle with a `MultiEffect`
shadow. Static search found the shell `InnerShadow.qml` wrapper as its only
consumer. The ordinary Fedora startup trace recorded no creation/compilation
event for `InnerShadow.qml` or `ExternalShadow.qml`. This does not cover an
edit-mode interaction, but gives no evidence that this path contributes to the
measured normal dock workload. Keep P5 deferred unless a concrete active
consumer and effect-on/off allocation or frame-time measurement identify a
cost worth changing.

### P6 — pure-QML build-time caching

`declarativeimports/components` is currently installed as a directory of loose
QML files and `qmldir`, not as a `QML_FILES` module target. The selected local
build's `.rcc/qmlcache` contained no cached QML source files. The Debug trace
recorded compilation activity, including 3 `ToolTip.qml` events totalling
9.62 ms; seven events with basename `main.qml` totalled 884.50 ms. Basename-only
grouping is ambiguous and is not a module-specific measure.
The candidate components module therefore has not shown material cost, and
converting it to a build-time module would alter build, install and user-QML
override behavior. Keep P6 deferred until a module-specific cold/warm Release
startup comparison and build/install prototype demonstrate a material benefit
with both supported QML roots verified.
