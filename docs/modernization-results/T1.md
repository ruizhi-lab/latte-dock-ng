## Promoted candidates

| Check | Fixture trigger |
| --- | --- |
| `bugprone-lambda-function-name` | Use `__func__` inside a lambda. |
| `bugprone-shared-ptr-array-mismatch` | Pass an array allocation to scalar `shared_ptr`. |
| `bugprone-sizeof-container` | Apply `sizeof` to `std::vector`. |
| `bugprone-string-integer-assignment` | Assign integer `42` to `std::string`. |
| `bugprone-suspicious-missing-comma` | Omit a comma between two of eight string literals. |
| `bugprone-terminating-continue` | Use `continue` in a `do` loop with constant false condition. |
| `bugprone-too-small-loop-variable` | Iterate a `long` upper bound with a `short` counter. |
| `bugprone-unique-ptr-array-mismatch` | Pass an array allocation to scalar `unique_ptr`. |
| `misc-misleading-bidirectional` | Include U+202E in a comment. |
| `performance-for-range-copy` | Copy each `std::string` from a range loop. |
| `performance-implicit-conversion-in-loop` | Bind a map entry to `pair<int, vector<string>>`, converting the key's constness. |
| `performance-inefficient-vector-operation` | Call `push_back` in a variable-bound counter loop without reserving. |
| `performance-trivially-destructible` | Default a trivial type's destructor out of line. |

The triggers follow the checks' documented patterns: [implicit conversion in a
loop](https://clang.llvm.org/extra/clang-tidy/checks/performance/implicit-conversion-in-loop.html),
[inefficient vector operation](https://clang.llvm.org/extra/clang-tidy/checks/performance/inefficient-vector-operation.html),
[too-small loop variable](https://clang.llvm.org/extra/clang-tidy/checks/bugprone/too-small-loop-variable.html),
[trivially destructible](https://clang.llvm.org/extra/clang-tidy/checks/performance/trivially-destructible.html),
[suspicious missing comma](https://clang.llvm.org/extra/clang-tidy/checks/bugprone/suspicious-missing-comma.html),
and [string integer assignment](https://clang.llvm.org/extra/clang-tidy/checks/bugprone/string-integer-assignment.html).

The existing `bugprone-unused-return-value` and `bugprone-use-after-move`
checks remain enabled, making 15 checks total.

## Excluded candidates

- `bugprone-empty-catch` and `misc-throw-by-value-catch-by-reference` emit
  their intended diagnostics, but also produce compiler errors because the
  production compile flags disable exceptions. The runner treats those
  compiler errors as a failed analysis, so their fixtures do not qualify.

No runner accommodation or production workaround was made. These candidates
can be reconsidered only with fixtures that pass the production flags and
runner's fail-closed analysis.
