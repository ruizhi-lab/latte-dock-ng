## Scope

Establish read-only, repeatable A/A measurements and select representative
scenarios before choosing a performance implementation. No code was changed and
no resource saving is claimed.

## Validation

The 2026-09-30 host check found no process named `latte-dock-ng` (`pgrep -x
latte-dock-ng` returned no PID). The read-only collector therefore could not
verify an executable, collect `/proc/<pid>/smaps_rollup`, or take CPU/scheduling
samples. `pidstat` is also unavailable on the host. The sample is unavailable,
not zero. No dock install, restart or pointer/window interaction was performed.
A host-binary `/usr/bin/latte-dock-ng --version` probe unexpectedly entered
Qt/Wayland startup and aborted when the sandbox denied `wl_display` creation
(`Operation not permitted`). `coredumpctl` recorded a 2.5 MiB SIGABRT dump; no
process or core file remains in the worktree. This environment probe was not a
functional test or performance sample.

The required profile needs a running, identified dock and a stable desktop
scenario. After that session is available, record its executable/build identity,
matching QML/plugin/helper roots, compositor and display configuration, then
collect five paired idle-visible A/A runs (30-second warmup, 60-second sample)
and the selected interaction scenarios from the performance protocol. Keep
personal window titles and configuration values out of the artifact. Do not
start P1/P2/P3 implementation work until this evidence supports a specific
work-reduction hypothesis and M5b desktop behavior has been checked.
