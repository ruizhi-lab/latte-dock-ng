# S3: Dynamic Connection Contract Review

Status: Complete review. Date: 2026-10-01. Start HEAD: `140e0df21`.

| Connection | Producer and signature | Receiver and lifetime | Decision |
| --- | --- | --- | --- |
| Preview activation | `Preview.qml` root signal `activate(string uuid)`; QML creates its meta-object at runtime. | `PreviewView::activate(QString)` forwards to the protocol writer; view owns the root item until helper exit. | Keep `SIGNAL`/`SLOT`. `QQuickItem` has no compile-time signal member. |
| Preview close | `Preview.qml` root signal `closeRequested(string uuid)`; same runtime owner. | `PreviewView::close(QString)` forwards to the protocol writer; same lifetime. | Keep `SIGNAL`/`SLOT`. |
| Desktop wrapping | KWin `org.kde.KWin.VirtualDesktopManager.navigationWrappingAroundChanged(bool)` on the session bus. | `AbstractWindowInterface` slot updates its local cache; the connection is bound to the receiver object. | Keep `SLOT` because `QDBusConnection::connect` resolves the remote signature at runtime. |

The preview root is checked for successful creation before either connection;
the existing `QObject::connect` return values are not checked. A future QML
signal rename would therefore leave card actions inert and produce a Qt
connection warning. The D-Bus `connect` return is checked and logs when false.
Both failure behaviors are pre-existing and no connection logic was changed.
Concise ownership and stale-state reasons were added beside the connections.

## Checks

- Host GCC and Clang Debug targets `latte-dock-ng`, `latte-dock-ng-preview` and
  `previewprocessunittest` built without warnings. The preview process test
  passed 1/1 with each compiler, including fake-helper UUID activation and
  close paths.
- Fedora 44 KWin D-Bus introspection confirmed the property and
  `navigationWrappingAroundChanged` signal both use boolean signatures. The
  wrapping setting was changed from false to true and restored to false.
- Fedora user-mode `latte-dock-ng-preview` loaded its QML and exited cleanly
  on stdin EOF, sending `{"serial":0,"type":"closed"}`. No missing-signal
  or connection warning appeared. Mesa emitted four DRI2 screen warnings in
  this standalone launch; these did not appear in the running Dock debug log.
- A live click on a preview card was not exercised: the user's normal task
  hover action disables previews. The fake-helper test proves the dock-side
  protocol path, while startup proves QML signal signatures can be connected;
  neither alone proves physical card hit targets. No runtime behavior changed
  in S3.
