# R3: Rule of Zero in `app/data`

Status: Complete.
Date: 2026-10-26. Branch: `main`. Implementation commit: see
`git log --grep 'refactor: let the compiler generate the data record members'`.

## Defect

`app/data` contained hand-written copy and move constructors and assignment
operators: thirty-one declarations over sixteen records, plus the two table
templates. Each one listed every field of its record again, and the move members
copied instead of moving (no `std::move` in `app/data`). Two consequences
followed:

- A field added to a record later was silently dropped by any special member
  that was not updated, because the code still compiled.
- Every record had to be maintained in three places (fields, copy order, move
  order) with no compiler check that they stayed in sync.

## Fix

The copy and move constructors and the two assignment operators are removed
from the sixteen `app/data` class headers (thirty-one declarations, sixty-two
member definitions). The compiler-generated defaults copy and move every member,
including members added later, so the classes follow the Rule of Zero.
`GenericData` and `GenericTable` carry the rationale comment; the other records
point at it.

The custom comparison operators (`operator==`, `operator!=`), the converting
`operator QString()`, the table helpers and `LayoutsTable::subtracted()` stay
hand-written: they express record semantics, not member-wise copying.

An empty `//! Operators` comment that was left without any operator behind it
in `activitydata.h` was removed with the members it described.

## Lock

`autotests/sourcecontracttest.cpp` adds `dataRecordsKeepRuleOfZero()`. It walks
every header in `app/data`, strips comments first, and rejects a declaration
that carries the record's own type in both parameter positions, which is the
only shape a copy or move special member has:

```
operator=(const Name &)      operator=(Name &&)
Name(const Name &)           Name(Name &&)
```

A back-reference is what separates a special member from an ordinary function
such as `LayoutsTable::subtracted(const LayoutsTable &rhs)`, which is why the
earlier pattern reported a false positive on that file.

The check was proven to fail on a regression: adding
`UniqueIdInfo(const UniqueIdInfo &o)` and
`UniqueIdInfo &operator=(UniqueIdInfo &&rhs)` back to
`app/data/uniqueidinfo.h` produced

```
FAIL! : declares a hand-written copy/move member: UniqueIdInfo(const UniqueIdInfo &o)
```

and restoring the file made the suite pass again.

## Deviation from the planned lock

The plan asked for the lock to be "clang-tidy scoped to `app/data`". clang-tidy
has no check for this direction: `cppcoreguidelines-special-member-functions`
requires all five special members to be declared, which is the opposite of the
Rule of Zero. A source contract runs in the normal `ctest` suite on both
compilers and fails on exactly the pattern this slice removes, so it is used
instead. The existing `bugprone-use-after-move` and
`bugprone-unused-return-value` gate on `app/data/errordata.cpp` is unchanged.

## Next action

None for R3. If a record ever needs a genuine custom copy (for example a deep
copy of a heap member), add it with a comment explaining why the generated
default is wrong and extend the contract to allow that single named case.
