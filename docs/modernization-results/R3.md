# R3: Rule of Zero in `app/data`

Status: In progress. The refactor in `478ba01ee` is verified, and the lock
below was strengthened after a review found a gap; the ledger row stays open
until it cites the commit that strengthens the lock.
Date: 2026-10-25. Branch: `main`.

## Defect

`app/data` contained hand-written copy and move constructors and assignment
operators: 62 declarations with 62 out-of-line definitions in 16 classes (15
records and the `GenericTable<T>` class template; `GenericBasicTable` declared
only the two constructors). Each one listed every field of its class again, and
the move members copied instead of moving (no `std::move` in `app/data`). Two
consequences followed:

- A field added to a record later could be dropped by any special member that
  was not updated, because the code still compiled.
- Every record had to be maintained in three places (fields, copy order, move
  order) with no compiler check that they stayed in sync.

## Fix

The copy and move constructors and both assignment operators are removed from
the 16 classes. None of them declares a destructor, so the compiler generates
all four members, which copy and move every member, including members added
later. The classes follow the Rule of Zero. The rationale is documented once on
`Generic` in [genericdata.h](../../app/data/genericdata.h), and
[generictable.h](../../app/data/generictable.h) points to it.

The custom comparison operators (`operator==`, `operator!=`), the converting
`operator QString()`, the table helpers and `LayoutsTable::subtracted()` stay
hand-written: they express record semantics, not member-wise copying.

An empty `//! Operators` comment that was left without any operator behind it
in `activitydata.h` was removed with the members it described.

## Lock

`SourceContractTest::dataRecordsKeepRuleOfZero()` strips comments from every
header in `app/data` and rejects a declaration that names the record's own type
twice, as a constructor name and its parameter or as an assignment return type
and its parameter:

```
Name(const Name &)    Name(Name &&)    Name &operator=(const Name &)    Name &operator=(Name &&)
```

Back-references tie the two names together, which keeps ordinary functions such
as `LayoutsTable::subtracted(const LayoutsTable &rhs)` out of the match. The
type may be qualified or carry template arguments (`GenericTable<T>`), and the
parameter may be named, unnamed, east-const or, for a copy-and-swap assignment,
passed by value. The test first checks its own pattern against twelve
special-member shapes and eight ordinary declarations, so a weakened pattern
fails in the suite.

The pattern committed in `478ba01ee` only matched an `operator=` whose
parameter had no name, and neither of its branches matched a template type. A
review re-added declarations to the headers and ran the real test binary:

| Re-added declaration | Pattern in `478ba01ee` | Strengthened pattern, GCC and Clang |
| --- | --- | --- |
| `UniqueIdInfo &operator=(const UniqueIdInfo &rhs);` | Passed: missed | Failed: rejected |
| `UniqueIdInfo &operator=(UniqueIdInfo &&rhs);` | Passed: missed | Failed: rejected |
| `UniqueIdInfo(const UniqueIdInfo &o);` | Failed: rejected | Failed: rejected |
| `UniqueIdInfo &operator=(UniqueIdInfo rhs);` | Not run | Failed: rejected |
| `UniqueIdInfo(UniqueIdInfo const &o);` | Not run | Failed: rejected |
| The four `GenericTable<T>` members removed by `478ba01ee` | Passed: missed | Failed: rejected |

Each header was restored after its case, and the unmodified tree passes. Run
against the headers as they were before `478ba01ee`, the strengthened pattern
flags all 16 headers that declared special members, including
`generictable.h`, which the first pattern missed. With the first pattern
swapped back into the test, the self-check fails on the first shape it misses,
`Activity(Activity const &);`.

## Deviation from the planned lock

The plan asked for a clang-tidy lock scoped to `app/data`. A source contract is
used instead. `cppcoreguidelines-special-member-functions` enforces "all five
or none": clang-tidy 22 leaves a Rule-of-Zero class alone and flags the exact
pre-R3 shape (four members without a destructor), but it accepts a complete
hand-written set of five. The repository's tidy gate also analyses only
`app/data/errordata.cpp`, in the Clang Debug CI job. The source contract rejects
every hand-written copy or move member in all `app/data` headers and runs in
CTest on both compilers. The existing `bugprone-use-after-move` and
`bugprone-unused-return-value` gate is unchanged.

The first version of this report said the check "requires all five special
members", counted thirty-one declarations and showed only the constructor
branch of the lock failing; this report replaces it.
