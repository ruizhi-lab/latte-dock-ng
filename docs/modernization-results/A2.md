## Evidence

`app/main.cpp::filterDebugMessageOutput` is installed as the process-wide Qt
message handler. It suppresses exact deprecated-binding messages, but also
contains substring filters for package/toolbox warnings, generated Plasma QML
resources, warning text from Qt/Kirigami types, clipboard load errors and
digital-clock internals. The handler affects what reaches the debug log, so
removing or narrowing a match without confirming its actual emitter can hide
an existing dependency failure or change log volume in either direction.

No readable `/tmp/latte-ng.log` was present during this review. More importantly,
the handler returns before writing a matched message, so an ordinary Debug log
cannot reveal which messages were suppressed. Source text alone cannot
establish which filters match on this supported runtime or whether any
candidate line is emitted by a project component.

## Decision

Defer all A2 production changes. This preserves current behavior and avoids
silencing or exposing diagnostics speculatively. The user-mode Debug install,
launch and retest procedure in AGENTS.md is required to collect representative
evidence. Use temporary, locally scoped diagnostic instrumentation immediately
before the filter's early return to capture bounded candidate messages and
`QMessageLogContext` metadata. Do not emit Qt log messages from inside the
handler, which would recurse; write directly to a bounded local diagnostic
sink. Associate the capture with its Plasma/Qt version and relevant interaction;
remove the instrumentation before finalizing a patch.
Where context metadata does not identify an emitter, correlate the message
with dependency source and the triggering interaction. A future A2 pass should
change one message family at a time and include a controlled check that an
unrelated warning remains visible.

No build or tests were run. `git diff --check` is the documentation hygiene
check for this handoff.

## Exact next action

Continue A3 source tracing. Keep A2 deferred until a bounded pre-filter
capture is available; do not change `filterDebugMessageOutput` based on guesses.
