# M6: Evaluate one useful internal dependency boundary

Status: Deferred.

## Baseline and decision

Recorded main baseline: `e3ef1ddf001aa032cffa62db21cfd97196174746`.
Evaluation HEAD: `a78a27ef6` on `codex/modernization-m0-baseline`.

The application is one `latte-dock-ng` executable. Its subdirectory
`CMakeLists.txt` files append sources to the parent executable. M5's
`BlockHidingEvents` is a header-only value helper and has no compiled source or
runtime dependency to move into a target.

The most apparent shared implementation candidate was
`app/wm/schemecolors.cpp`, which the main executable and
`schemecolorsunittest` both compile. The file also calls app-owned
`Latte::configPath()` and `Layouts::Importer::standardPath()`. The test supplies
stubs for those app services. Moving this file to a static library would avoid
one repeated source compilation, but the executable would retain its existing
KConfig/Qt dependencies and the library would still rely on app-layer services.
That creates another target without reducing dependency ownership or runtime
cost; the benefit is too small to justify the extra link/AUTOMOC boundary.

## Evidence

- `codegraph explore "SchemeColors class app/wm/schemecolors.cpp consumers schemesmodel.cpp"` — traced uses in the theme, settings model, window tracker and focused test; current `schemecolors.cpp` calls app config and layout-import services.
- `rg -n '^add_(library|executable)|^qt_add_' app/CMakeLists.txt autotests/CMakeLists.txt` — app subdirectories contribute to one executable; focused tests are separate executables.
- `sed -n '1,145p' app/CMakeLists.txt` and `sed -n '434,463p' autotests/CMakeLists.txt` — confirmed current target/source ownership and duplicated `schemecolors.cpp` compilation.
- `sed -n '20,110p' autotests/schemecolorsunittest.cpp` — confirmed the test provides `configPath` and `Importer` stubs, so the source is not an independent library boundary.

No production code, CMake targets, install rules, or dependencies changed. No build was needed for this documentation-only decision.

## Handoff

Keep M6 deferred. Reopen only when profiling or a concrete dependency review
shows a boundary that removes a real dependency, duplicated production
implementation, or meaningful build cost. Do not add targets solely for
organizational symmetry.
