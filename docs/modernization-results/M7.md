# M7: Explicit Nix checks and development environment

Status: Pending validation.

## Scope

Add an x86_64-linux development shell and an explicit test derivation using the
release derivation's dependency inputs. The test derivation builds the actual
application host and autotests, then runs CTest with a private D-Bus session and
offscreen Qt. Keep `flake.lock` unchanged and keep test tools outside the
release package runtime closure.

## Validation

Implemented in `flake.nix`: `checks.x86_64-linux.autotests` derives from the
release package dependencies, enables CTest, builds the application host and
autotests, and runs them under offscreen Qt and a private D-Bus session.
It adds the Breeze icon package only to the test derivation and points the
core icon assertions at that store path; the release runtime closure stays
unchanged.
`devShells.x86_64-linux.default` reuses the package inputs and adds development
tools. The NixOS verification script now runs flake check, the default package
build, and a preset build inside that same verified image. `flake.lock` is
unchanged.

Local checks: `bash -n docker/verify-nix-nixos.sh` and `git diff --check` pass.
The local host has no `nix` executable (`nix --version` exited 127), but the
cached `nixos/nix:latest` container reports Nix 2.35.2 and
`nix-instantiate --parse flake.nix` exited 0. Full flake evaluation/build,
CTest and the dev-shell preset reached CI. Run 36637219288 confirmed the flake
evaluation and release derivation, then found that the existing color test used
the legacy `<KConfigGui/kconfiggui.h>` include, which is unavailable in the
current Nix KF6 package. The test now uses KDE's documented public
`<KConfigGui>` header. Both GCC Debug and Clang Debug `schemecolorsunittest`
builds and focused CTest runs pass with this include. Run 36639481756 compiled
the full application and autotest aggregate successfully, then failed before
CTest because the Nix sandbox has no `/etc/dbus-1/session.conf`. The check now
passes the Nix-provided session config explicitly to `dbus-run-session`; CI
must rerun before this batch can complete. Run 36642361102 then evaluated the
flake, built the application and complete autotest aggregate, and ran CTest;
41/46 tests passed. The next revision, run 36645587779, passed 42/46. Its four
failing targets were `coreunittest`, `qmlsmoketest`,
`pluginregistrationunittest`, and `windowviewbackendtest`. The second run showed
that check-phase Qt paths were exported too late for CMake's configure-time
`qmlplugindump` probes; the Qt SVG image plugin was also missing from the
test-only runtime search path, so Breeze icons could not load. CMake resolves
`dbus-run-session` to an absolute path during configuration, which made the
PATH wrapper ineffective for the nested test. The test derivation now exports
Qt/QML and Fontconfig paths from `preConfigure`, includes QtSvg, and passes an
optional D-Bus session config through test registration. The process tests use
their own executable as a portable fallback target. Focused GCC and Clang
builds and CTest for `wmunittest` pass; this revision still requires CI. Locally,
`dbus-run-session --config-file=/usr/share/dbus-1/session.conf -- true` parsed
the config but the managed sandbox denied its temporary socket bind, so the
full invocation remains a CI check.
