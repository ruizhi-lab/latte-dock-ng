## Defect

The three settings windows built on `SubConfigView` handed their C++ objects to
QML as context properties: 21 `setContextProperty()` calls in
[app/view/settings](../../app/view/settings) at the start HEAD, 18 of them in
the window classes and 3 in `IndicatorUiManager`. QML read them
unqualified, so qmllint could not see them (142 `unqualified` diagnostics in the
three root files), a root property named like its input could not bind to it
(hence the `configuration*` aliases), and a dock switch needed a hand-written
update for each name that pointed at the dock.

in `indicatoruimanager.cpp` (`indicator` twice, `dialog` once): 18 calls removed.

## Fix

**Delivery.** [subconfigview.h](../../app/view/settings/subconfigview.h) gets two
protected helpers and a documentation block that states the contract.
`setRootInput(name, object)` records the value (guarded by a `QPointer`) and, once
the root exists, writes the root property. `loadRootSource(url)` replaces
`setSource()` in the three `init()` functions: it calls
`QQuickView::setInitialProperties()` with the recorded inputs first, so the
root's bindings, the settings Loader's `active` guard and the dynamic indicator
pages created during completion never see an undefined input. A write to a
property the root does not declare returns false and is logged, instead of
creating an unread dynamic property.

**Declarations.** Every root declares the same six inputs, or Qt logs "Setting
initial properties failed: ... does not have a property called ..." and leaves
the input unset:

| Root | Type of the inputs | Why |
| --- | --- | --- |
| `LatteDockConfiguration.qml`, `CanvasConfiguration.qml` | `QtObject` | A deleted dock clears the property and notifies, so the Loader unloads its tree |
| `WidgetExplorer.qml` | `var` (as before) | `QtObject` adds ten `missing-property` diagnostics for members of `viewConfig`, `themeExtended.isDarkTheme` and `containmentFromView.applets` |

Files below a root keep reading the names unqualified: QML resolves a name
through the context chain up to the root object of the window's QML file, so the
pages needed no edit. The dialog and the canvas' inner root copy the inputs from
the Loader explicitly (`configurationLoader.latteView`); a property that reads its
own name binds to itself. `plasmoid` has no dialog-level copy: see the
experiment below.

**Dock switch.** `PrimaryConfigView` is shared by all docks and re-points its
canvas window. `PrimaryConfigView::initParentView()` clears `isReady` (the
Loader unloads the tree), `SubConfigView::initParentView()` publishes
`latteView` and then `plasmoid`, as it did as context properties, and `isReady`
is set again. The retry that waits for the containment's graphic object publishes
`plasmoid` each time. The widget explorer's own input, `containmentFromView`,
goes through the same helper and now follows a switch too; before it was set once
after `setSource()`.

**Dock destroyed.** `PrimaryConfigView` also sets `isReady` false when its dock
is destroyed. `QObject::destroyed` is emitted before the QML engine releases its
guards on the object, so the tree is unloaded before any binding is
re-evaluated against the dying dock. The window stays orphaned until another dock
adopts it (`ViewSettingsFactory::hasOrphanSettings()`), and `initParentView()`
sets `isReady` again.

**Cleanup.** `SubConfigView::syncPlasmoidContext()` and its counters were renamed
to `syncPlasmoidInput()` and friends, the unused shortcuts includes were
dropped, and [architecture-overview.md](../architecture-overview.md) points to
the contract. `docs/architecture-modernization-plan.md` is not touched; the main
session updates the ledger.

## State authority and lifetime

- The authoritative dock is `SubConfigView::m_latteView` (a `QPointer`).
  `m_rootInputs` is a guarded copy of the last published value of each input; it
  matters only until the root exists.
- A stale retry of `syncPlasmoidInput()` resolves the current dock when it runs,
  so a timer left over from a previous dock publishes the current plasmoid.
- Third-party indicator UIs are not reachable from root properties (separate
  engine); their two context properties are unchanged.

### Qt behavior the design relies on

Standalone offscreen experiments (sources in the shared notes folder,
`r4-settings-root-inputs-experiments`, not in the repository) on Qt 6.11.2:

- `setInitialProperties()` values are in place before the root's bindings run,
  and files below the root read all six names unqualified.
- `setProperty()` after creation updates the root, and a nested binding follows.
  `QObject::setProperty()` returns false for an undeclared name.
- An undeclared initial property logs "Setting initial properties failed: Root
  does not have a property called ..."; the root is still created and the other
  inputs are set.
- A deleted dock, tree with a Loader guard, `Page` files that read a `var` copy
  of the input and a child file that reads names unqualified:

| Design | Dock destroyed: TypeErrors, Loader active | Plasmoid destroyed |
| --- | --- | --- |
| Old context properties | 0, false | 0, false |
| `QtObject` root inputs, `var` copies (this change without the guard) | 4, false | 0, false |
| `var` root inputs, `var` copies | 4, true (stale tree) | 0, true |
| `QtObject` root inputs and `isReady` cleared first (this change) | 0, false | 0, false |
| `var` root inputs and `isReady` cleared first | 0, false | 0, true |
| `QtObject` root inputs plus a dialog-level `var plasmoid` copy | 4, false | 2, false |

These come from a toy tree, not from the real settings window; the desktop retest
covers the real one.

What the log corroborates:

- **The trees were built with the root inputs.** 31 QML cache files were written
  between 22:27:59.437 and 22:27:59.970: `CanvasConfiguration.qml` with its canvas

  `IndicatorConfigUiManager`, `CustomIndicatorButton`,
  `CustomVisibilityModeButton`, `HelpMenuButton` and the Latte components. A cache

  re-pointed at the other dock at 22:34:12. At 22:35:26 both docks, including the
  one the window pointed at, were destroyed while the windows existed, and the
  dock created in their place was destroyed again at 22:35:33 (the path the
  `isReady` guard covers; the guard writes no log line). The log still holds the
  same eight World Clock warnings and nothing else: no initial-property,
  TypeError, ReferenceError or binding message from a Latte file.
- **No crash.** 113 `latte-dock-ng` coredumps before and after; the dock was
  still running at 22:36.

What rests on the user's report because it writes no log line: page visits,
indicator style changes (the only installed custom indicator is Plasma Tab
Style, which has no options UI) and canvas handle use.

Not exercised: a dock recreated while the window is visible, where the new dock

dock while the window is visible takes the same path as the 22:34:12 switch,
because `PrimaryConfigView::setParentView()` hides the window before it calls
`initParentView()` in both cases.
