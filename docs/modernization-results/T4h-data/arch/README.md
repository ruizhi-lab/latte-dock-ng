# Arch Plasma 6.8 validation for T4h

The validation VM is Arch Linux on kernel `7.2.15-arch1-1`, with `libplasma 6.8.2-1`, `qt6-base 6.12.0-5`, Clang/LLVM `23.1.4-1`, GCC `16.2.1`, and CMake `4.5.0`. The source tree was an isolated `/tmp/latte-modernization-20261114-src` archive of commit `d77eef90245a8571b05d489fbc10d6cd9f94998d` plus the frozen T4h changes, the two-line Views sorting rationale, and the one-line `environment.cpp` T4g fix described below. The compile database is `/tmp/latte-modernization-20261114-src/build/modernization/clang-debug/compile_commands.json`.

## Results

- The fresh Clang Debug configure succeeded. CMake 4.5 emitted four author warnings for generated QML type metadata used by install rules for the core, private app, private containment, and private tasks plugins. The exact configure log is [clang-configure.log](clang-configure.log); no suppression was added.

These QML diagnostics were not compared with a same-SDK baseline. The additional targets build log is [clang-build-all.log](clang-build-all.log).
- The CI-version `clang-tidy 18.1.3` wrapper ran from `/tmp/latte-llvm18`. Its `ldd` output resolved the actual copied `libxml2.so.2.13.9`, `libicuuc.so.78`, and `libicudata.so.78` files in that isolated tool directory, with no missing libraries or SONAME alias. The local's `const` was removed; its string and returned `QVariant` value/type are unchanged. The initial finding is preserved in [clang-tidy18-pre-environment-fix.log](clang-tidy18-pre-environment-fix.log), and the focused check after the fix passed in [environment-focused18.log](environment-focused18.log).
