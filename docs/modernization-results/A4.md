## Traced source of truth and fallback

- `Corona::screenForContainment()` resolves nested applet containments first,
  then asks `Layouts::Synchronizer` for the layout-owned screen.
- `Synchronizer` finds the owning `GenericLayout`; that layout resolves a
  pending containment update first, then a live or waiting view's screen using
  `ScreenPool` connector identity.
- If there is no layout mapping, `GenericLayout` returns Plasma's
  `containment->lastScreen()`. `Corona` also uses `lastScreen()` if the
  synchronizer returns a negative value.
- `ScreenPool` persists connector-to-screen-ID mappings and tracks output
  changes. This supports the source comment's conclusion that transient
  `QGuiApplication::screens()` ordering should not be used as persistent
  identity.
